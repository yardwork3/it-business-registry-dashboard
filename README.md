# Панель ИТ-компаний в Едином реестре МСП

Streamlit-приложение показывает вход, повторный вход, непрерывные переходы в ИТ, выход из реестра и удержание когорт. Расчёты следуют определениям статьи `article_DIGITAL2027.docx` и не имеют причинной интерпретации.

## Методология

- `IT_CORE`: основные коды ОКВЭД `62.*` и `63.1*`.
- Контроль: `70.*`, `71.*`, `82.*`.
- Самозанятые (`kind = 3`) и записи без ОКВЭД или региона исключаются.
- В сокращённое хранилище попадают только ИНН, когда-либо наблюдавшиеся в ИТ или контроле, но для них сохраняется полная история кодов ОКВЭД. Это необходимо для корректного выявления переходов из других отраслей.
- `start_date` и `end_date` — границы актуальности версии, а не даты создания и ликвидации бизнеса.
- Месячные состояния строятся на 10-е число каждого месяца.
- Первый вход — первое наблюдаемое присутствие ИНН в реестре.
- Повторный вход — возвращение после разрыва хотя бы в один месячный снимок.
- Переход в ИТ — смена не-ИТ кода на `IT_CORE` без пропуска месяца.
- Выход — первый отсутствующий месяц после непрерывного эпизода; он не равен закрытию бизнеса.
- Наблюдения на 10 июня 2024 года считаются правосторонне цензурированными.
- При перекрывающихся версиях состояние выбирается детерминированно по наиболее позднему `start_date`, затем `end_date` и коду ОКВЭД.
- Удержание через 6 и 12 месяцев относится к первому непрерывному эпизоду и считается только для когорт с полностью наблюдаемым горизонтом.

## Подготовка данных

```powershell
python scripts/prepare_data.py
```

Скрипт создаёт локальную `data/registry_dashboard.duckdb` со следующими основными таблицами:

- `eligible_tins` — идентификаторы организаций, когда-либо относящихся к ИТ или контролю;
- `panel_reduced` — необходимые поля и полная история ОКВЭД этих организаций; локальная копия также сохраняется как `data/private/panel_reduced.parquet`;
- `firm_month` — состояния на 10-е число месяца;
- `firm_month_events` — состояния и классифицированные события;
- `dashboard_monthly` — обезличенные месячные агрегаты;
- `dashboard_retention` — обезличенные агрегаты удержания когорт.

Файлы DuckDB, каталог `data/private`, временные файлы, CSV и любые микроданные исключены из Git. Стабильная база приложения содержит только агрегаты. Демонстрационные Parquet не содержат ИНН и других идентификаторов.

## Запуск приложения

```powershell
streamlit run app.py
```

Если локальная база присутствует, приложение использует полные агрегаты. Если базы нет, оно автоматически открывает небольшой демонстрационный набор.

Фильтры:

- период;
- регион;
- вид субъекта;
- категория МСП;
- отрасль.

Визуализации построены на Plotly и включают фонд ИТ-компаний, первые и повторные входы, переходы в ИТ, выходы из реестра, удержание через 6 и 12 месяцев и сравнение с контрольными отраслями.

## Тесты

```powershell
pytest -q
```

Тесты проверяют различение первого и повторного входа, непрерывного перехода, выхода, правило непрерывного первого эпизода и исключение микроданных из Git.

## Ограничения интерпретации

Показатели описывают изменения наблюдаемого присутствия и основного ОКВЭД в реестре. Они не доказывают создание или ликвидацию бизнеса, мотив смены кода, фактическую структуру выручки либо причинный эффект мер поддержки.
